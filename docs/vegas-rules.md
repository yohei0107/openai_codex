# ラスベガスの判定仕様

## 根拠と確認状況

この機能はユーザー指定の「バーディーで相手の数字を反転」「相手の同スコア時に倍率増加」「リーチ／プッシュでそのホールの得点を倍にし、複数回使用できる」というルールに基づきます。ゾロ目時の加算・乗算は両方存在し、ゲーム開始前に選びたいとの追加指示を反映しています。

公開記事の本文による裏付けは未確認です。公式に統一されたルールであるとは主張していません。以下の境界条件はアプリ内で明示した取り決めです。

## 開始と保存

新しいラウンドでは、開始前の設定画面でバーディールールの有無とゾロ目時の倍率方式を選びます。「このルールで開始」で確定し、以後は編集できません。プッシュ回数はホールごとに変更できます。

旧保存データで `vegasRules` が存在しない場合、バーディールールなし・プッシュ0回として以前の集計を保持します。保存キーとversionは維持し、新しいフィールドは旧データでは省略可能です。旧ラウンドに新ルールを遡って強制適用しません。

## 計算順序

1. 前ホールのスコア順でオナーを決め、設定された順位のプレイヤーと組みます。初回はプレイヤー順、同点は直前の順番を維持します。
2. チーム内のスコアを昇順に並べ、小さい方を十の位、大きい方を一の位にします。
3. パーよりちょうど1打少ないスコアの人がいるチームは、相手の数字を1回反転させます。同じチームに2人のバーディーがいても1回。両チームにいれば双方へ同時に適用します。
4. 反転されるチームの2人が同じスコアなら、ゾロ目の倍率増加を1件として数えます。反転されても数字は変わりません。
5. プッシュ倍率は `2 ** プッシュ回数`。ゾロ目の件数を `z` としたとき、最終倍率は「2倍」方式なら `プッシュ倍率 × 2 ** z`、「1加算」方式なら `プッシュ倍率 + z` です。
6. 反転後のチーム数字の差に最終倍率を掛けます。小さいチームの各メンバーに加点、相手に同数を減点します。

両チームの数字が同じなら倍率があっても0ポイントです。「相手の2人が同スコア」と「チーム間の引き分け」を混同しません。

## 制限と対象外

- 1〜9打を全員入力したホールのみ計算します。未入力や10打以上は、そのホールを未計算として表示し集計から除外します。
- プッシュは0〜30回。UIから減算・解除できます。上限はJavaScriptでラウンド合計まで整数精度を維持するためのアプリ上の制限です。
- プッシュ回数だけを管理します。宣言者・宣言タイミング・受諾・チーム間の宣言順序の判定は行いません。
- イーグル等の追加反転・倍率、同チームの複数バーディーによる効果の重複、次ホールへの繰越はありません。
- チーム分けは従来どおり3種類から選びます。金額・精算は扱いません。

## 調査記録（2026年10月20日・日本時間）

以下はアクセスを試した検索先であり、ルールの根拠として引用した資料ではありません。

- [Google検索](https://www.google.com/search?q=ゴルフ+ラスベガス+バーディ+ゾロ目+プッシュ+ルール)：初期HTMLは取得できたものの検索本文を含まず、JavaScript実行後の検索要求はHTTP 429。TLS検証を無効にはしていません。
- [ALBAサイト内検索](https://www.alba.co.jp/articles/search/?text=ラスベガス)：検索結果を取得。都市・大会に関する記事が中心で、指定されたゲームルールを裏付ける記事は確認できず。
- [ゴルフパートナーサイト内検索](https://www.golfpartner.co.jp/mt/mt-search.cgi?search=ラスベガス)：既定の検索範囲では該当なし。全ブログの検索はサイト側でタイムアウト。
- Bing、DuckDuckGo：ネットワークポリシーによりHTTP 403。代替検索先2ドメインを環境設定案に追加。保存しただけでは現在のネットワークに適用されません。

今後、外部資料で同一チームの複数バーディー、双方のバーディー、イーグル、プッシュの宣言条件などの差異を確認する必要があります。
